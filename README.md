## 3단계 가설 검증

### ① 우리 서비스를 사람들이 원하나? — `아이템 검증 성공` · `사용자 유지 실패`

**문제**
- 다이어리, 알람, 캘린더, 목표별 앱(운동·언어·자격증)이 흩어져 있어 불편해요.
- Task를 하는 이유는 결국 목표 때문인데, 둘을 합친 앱도 없고 목표별 시간 사용량과 효율적인 시간대를 분석해 주는 서비스도 없었어요.
- 반면 수요 신호는 있었어요. 루틴 그래프가 국내외 유튜브에서 바이럴됐고, iOS 캘린더 위젯 스레드는 100만 회 조회됐어요.

**해결**
- 목표 세분화, 일/주/월 캘린더, 시간 패턴 그래프로 MVP를 기획하고 **1주일 만에 개발·출시**했어요.
- 브랜딩은 '공감, 함께' 컨셉으로 잡았어요.
- 유입은 인스타그램 광고 하루 5천 원 × 7일로 최소 비용 테스트를 했어요.

**성과**
- 출시 8일 만에 활성 사용자 **796명**, 회원가입 **140명**, CAC **88원**이 나왔어요.
- 광고를 늘린 뒤에도 CAC **100원**을 유지했고, 회원가입이 150명씩 늘었어요 → **아이템 검증 성공**
- 하지만 리텐션은 **9%**에 그쳤어요 → 사용자 유지 실패

### ② 우리 서비스에 돈을 낼까? — `수익화 검증 부분 성공` · `사용자 유지 실패`

**가설**
- 혼자서는 목표 실행을 미루기 쉬워서 이탈했을 것이다.
- 방문자의 96%가 모바일인데 매일 확인하는 캘린더가 모바일을 지원하지 않아서 이탈했을 것이다.

**해결**
- 횟수 제한형 **Free / Pro 구독 BM**을 출시했어요.
- iOS 사용자 비중(80%)을 근거로 **iOS 앱을 출시**했어요.
- 친구와 목표를 함께하는 **커뮤니티(미션) 기능**을 추가했어요.

**성과**
- 1주일 동안 월간 구독 결제 **3건**이 발생했어요. 적은 건수지만 수익화가 가능하다는 걸 확인했어요.
- 리텐션은 **2.3%**로 여전히 사용자 유지에 실패했어요.

**회고**
- **iOS 출시:** 메인 타깃인 20대 중후반은 노트북·데스크톱으로 일을 처리해요. 그런데 분석 툴에서 'iOS 사용자가 많다'는 숫자만 보고 성급하게 일반화했어요.
- **커뮤니티:** 사용자들이 커뮤니티 기능까지 도달하기 전에 이탈해서 검증 자체가 안 됐어요. 핵심 가치 전달과 함께 달성하는 보상이 부족했던 것으로 봐요.
- **가설 설정:** 빠른 출시를 위해 근거 없이 직감으로 기획했더니, 문제의 핵심을 놓쳐 오히려 시간이 더 걸렸어요.

> **→ 데이터 없이 직감으로 세운 가설은 위험하다. 데이터 기반 의사결정과, 문제의 본질을 묻는 질문의 중요성을 배웠습니다.**

### ③ 어떻게 하면 계속 쓰게 만들까? — `리텐션 향상 · 진행 중`

**문제 정의**
첫 릴리즈(9/19~9/28)는 결제 전환 **1.4%**, D1 **17.9%**, D7 리텐션 **2.3%**였어요. 리텐션이 낮아서 결제까지 이어지지 않는다고 봤어요.

**퍼널**

```
랜딩 방문 1,129 → 스토어 클릭 453 (40%) → 다운로드 243 (53%) → 활성 사용자 217 (89%) → 결제 3 (1.4%)
```

**원인 분석 (이벤트 데이터 기반)**
1. **과정이 많고 전부 수기 입력이에요.**
   - 첫 목표부터 Task 생성까지 약 **12분**이 걸려요.
   - 단계마다 이탈이 커요: 온보딩 62.6% → 전체 목표 35.6% → 세부 목표 71.4% → Task 68.7%
2. **무엇부터 해야 할지 몰라요.**
   - 온보딩을 skip한 **56%**는 의도한 흐름을 탄 사용자보다 이탈률이 **3배** 높았어요.
3. **가치를 느끼기 전에 한도에 막혀요.**
   - 횟수 제한에 걸린 사용자는 나를의 가치를 충분히 경험하지 못하고 기존 캘린더로 돌아갔어요.

**해결 전략**
핵심 가설은 이거예요: *"나의 패턴으로 목표 달성률 높이기"를 7일 안에 경험하면(Aha-moment) 계속 쓰고, 결국 결제한다.*

| 전략 | 실행 |
|---|---|
| **AI 자동 생성** | AI가 목표·Task 초안을 만들고, 사용자는 승인·수정만 해요. 단계 구조는 유지하면서 소요 시간과 이탈을 줄여요. |
| **떠먹여주는 UX** | `목표 → Task` 구조를 `Task → 목표`로 뒤집었어요. 브레인 덤프로 할 일만 적으면 목표에 자동 연결되고, 첫 화면은 오늘의 TimeBlock부터 보여줘요. |
| **경험 중심 BM** | Free 경험 범위를 넓히고, AI 한도는 주·월 단위로 조정했어요. 비용은 광고 BM(AdSense · AdMob)으로 충당해요. |

**성과 측정 설계**
"사용자는 원하는 것을 달성할 때 앱의 가치를 느낀다"고 정의하고, 운영 대시보드로 기간별 지표를 모니터링하고 있어요.

| 구분 | 지표 | 정의 |
|---|---|---|
| 진입 | **Aha 도달률** | 가입 7일 내 목표 2개 생성 + Task 3개 완료 + 3일 이상 방문 |
| Main | **목표 달성률** | 달성 ÷ 기한이 끝난 목표 (결과) |
| Sub | **Task 실천률** | 완료 ÷ 해야 했던 Task·루틴 (과정) |
| AI | **직접 vs AI 목표** | 두 목표의 달성률·실천률 비교, 기능별 초안 승인·수정·삭제·재생성 비율 |

→ 이 지표들이 오를 때 최종적으로 **D7 리텐션(2.3%)과 결제 전환(1.4%)이 함께 오르는지** 검증하고 있어요.
